========================================
  在终端里用 Claude Code 命令行版
  Claude 稳定网络环境配置工具（macOS 版）
========================================

★ 只在浏览器里用 Claude 的，这份文档不用看。
★ 用 Claude 桌面端 App 的，也不用看 —— 桌面端只要「系统代理」
  开着就能用，不需要任何额外设置。

这份文档只写给一种人：要在「终端」里敲 claude 命令的。


========================================
  一、为什么必须单独配
========================================

光打开「系统代理」是不够的。

系统代理只管浏览器和 Claude 桌面端 App。终端里的命令行程序
不看这个开关 —— 流量会直接从你本机的国内 IP 出去。

★★★ 最要命的是：它不会报错 ★★★

  你会以为自己配好了，实际上一直在用国内 IP 访问 Claude。
  这比不配还危险 —— 不配你至少知道自己没配。

  这个工具存在的全部意义就是让 Claude 只看到你的美国住宅 IP。
  这一处漏了，前面所有步骤都白做。


========================================
  二、怎么配
========================================

端口号看你自己的《使用须知》开头那一行「专用端口」，
或者运行日志里也有。下面用 7896 举例，
★ 你要换成自己的那个数字 ★


【方式一：临时用，只对当前这个终端窗口有效】

    export HTTPS_PROXY=http://127.0.0.1:7896
    export HTTP_PROXY=http://127.0.0.1:7896
    claude

  关掉窗口就失效。适合偶尔用一次。


【方式二：一劳永逸，以后所有新开的终端都有效】

    echo 'export HTTPS_PROXY=http://127.0.0.1:7896' >> ~/.zshrc
    echo 'export HTTP_PROXY=http://127.0.0.1:7896' >> ~/.zshrc

  写完要「新开一个终端窗口」才生效，当前这个窗口不会变。

  macOS 现在默认用的 Shell 是 zsh，所以写进 ~/.zshrc。
  你要是自己把 Shell 换成过 bash，就写进 ~/.bash_profile。
  （不确定的话在终端里跑 echo $SHELL，看结尾是 zsh 还是 bash。）

  注意：这是全局的，同一个终端里的 npm、git、curl 也会跟着
  走美国住宅 IP，会慢一点。介意的话就用方式一。


【方式三：只让 Claude Code 走代理，别的程序不受影响】

  在 Claude Code 的 settings.json 里加一个 env 块：

      {
        "env": {
          "HTTP_PROXY": "http://127.0.0.1:7896",
          "HTTPS_PROXY": "http://127.0.0.1:7896"
        }
      }

  改完要重启 Claude Code。

  这个方式最干净，但我没有在所有版本上验证过 ——
  如果改完之后按第三节一验还是不对，就退回方式一或方式二。


========================================
  三、怎么确认真的走上了
========================================

在终端里跑（端口换成你自己的）：

    curl -x http://127.0.0.1:7896 https://ipinfo.io/ip

显示的是你 ISP 的那个美国 IP  →  对了
显示别的 IP，或者是国内 IP    →  没走上，回第二节重配

★ 千万别用「能不能打开 Claude」来判断。

  从香港、日本的节点也能打开 Claude 的部分服务，但那不是我们要
  的出口，账号该出事还是会出事。只有「出口 IP 等于你的 ISP IP」
  才算真的配好。


========================================
  四、要注意的几点
========================================

· Clash Verge 必须开着。
  这个端口是 Clash 提供的，Clash 一关就全断。
  好在这种情况会明确报错，不会静默走错路。

· macOS 上还有一个坑：Clash 的「系统代理」开关不影响 curl。
  也就是说，你在 Clash 里看到系统代理是开的，terminal 里 curl
  出去的还是国内 IP —— 这不是配置坏了，就是本文第一节说的那件事。
  要在终端里走代理，只能靠上面那几个环境变量。

· 光为了命令行，不必特意去开 TUN（虚拟网卡）模式。
  设环境变量这条路更精确、也更好排查，上面那几行就够了。

  ★ 但如果你已经因为「系统代理开关点不动」而开了 TUN
    （见《用前必读_Mac.txt》里那一节），那没问题 ——
    TUN 和这里的环境变量不冲突，两个都留着即可。
    TUN 模式下命令行本来也能走上代理，环境变量只是让它更确定地
    走我们这条专用链路，不必依赖分流规则。


========================================
  五、端口别填错：两个端口不是一回事
========================================

  你会在两个地方看到端口号，用途不同。填反了**不会报错**，
  只会悄悄出问题 —— 这是最难自己发现的一类。

  【本工具的专用端口】（就是上面那几行环境变量里的那个）

      给 Claude Code 命令行用。
      它直通出口组，流量走那条美国住宅 ISP，绕开分流规则。
      这正是我们要的 —— Claude 必须从住宅 IP 出去。

  【Clash 自己的混合端口】（在 Clash Verge 的设置里能看到）

      给其它工具用，比如别的 AI 命令行、别的程序。
      它走分流规则：该直连的直连，该走机场的走机场。

  ★ 其它工具建议指向 Clash 的混合端口，不是专用端口。

      不是因为省钱 —— 那些流量本来就要过机场，机场配额消耗一样，
      而美国住宅 ISP 是按月按 IP 收费、不限流量的，多绕一跳不额外花钱。

      理由是：专用端口绕开分流规则、还多一跳，延迟更高；
      而且大家挤在同一条 ISP 链上，Claude 这边反而可能受影响。
      别的工具走混合端口、按规则分流，各走各的更稳。

  ★ 反过来同样要注意：Claude Code 别指向 Clash 的混合端口。

      那样它会走分流规则，未必落在住宅 IP 上。
      而「看起来能用」恰恰是最危险的状态 ——
      你以为配好了，实际出口是机场的公共 IP。

· 如果你还开着别的梯子 / 加速器，请完全退出
  （菜单栏图标里选「退出」，不是关窗口）。
  两个代理软件会互相抢，浏览器和命令行可能走不同的出口，
  排查起来非常痛苦。
